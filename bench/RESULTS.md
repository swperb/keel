## Caveats

- `par_sum` is not Bend's exact demo. The demo sums 2^16 numbers as a `Nat`, which Bend caps at 2^48, so it cannot run past d = 24. Here Bend sums 2^30 numbers as a wrapping 32-bit U32; Keel and Rust compute the exact sum in i64 and print it mod 2^32, the same value.
- The Keel 1-core column is this runner's construction: Keel has no thread-count option, so the runner recompiles Keel's emitted C with the `par` spawner capped at one live thread (every `par` runs inline).
- Bend's GPU CPU times count host CPU only; the GPU's work shows only in the GPU wall time.
- The machine was shared with other work during the run (load averages above). Run-to-run noise is real: earlier single runs on the busy machine had Keel's `par` 2-3x slower than rayon on several programs, while these 5-run medians are close, so small gaps between columns may be noise. `results/results.json` has every sample.
